For the European Accessibility Act

Transactional emails everyone can read.

Order confirmations, shipping updates, password resets and sign-in alerts that work with a screen reader, a magnifier, a phone and tired eyes. They're built with Hyper Elements and can't be sent if they break.

Since 28 June 2025, the European Accessibility Act requires online shops in the EU to make their services accessible, and the emails customers get are part of them. Most fail without anyone noticing, because nobody on the team hears them the way a screen reader user does. Readable shows you, and fixes it at the template.

    {{OWN}} rules Hyper Elements didn't have
    
    
    Hyper Elements' lint already checks contrast, alt text, link text, headings and language. Readable adds what it doesn't, as a plugin over the same laid-out template. Each rule names its WCAG 2.2 success criterion, and a template that requires a rule can't pass while the rule finds something.

    How it works
    
    
    Readable is three things, each using Hyper Elements the way it's meant to be used.
    
    
    
      
    
        
    1. A plugin that templates require
    
        
    readable() is a lint plugin. It runs @hyper-elements/lint, adds {{OWN}} rules, and describes them the way lint describes its own. So a template requires them in rules.require.lint, and check() fails closed: if a rule finds something, or doesn't run, the email isn't sent.
    
      
    
      
    
        
    2. Four templates that pass all {{REQUIRED}}
    
        
    Each is a template() with typed fields: an order number pattern, a six-digit code the template groups as "482 913", a carrier it builds the tracking link for. Its words come in four languages, and its links can only go to the shop and the carrier. Every rule is required, in every language.
    
      
    
      
    
        
    3. A report for each
    
        
    The template's check() results, mapped to WCAG 2.2 criteria, become a Hyper Elements Document template printed to PDF. It lists what passed automatically, what Hyper Elements' output guarantees, and what a person still has to confirm.
    
      
    
    
    
    
    The plugin, in a template
    

    // One plugin: lint's {{LINT}} rules, and Readable's {{OWN}}.
import { readable } from "./src/wcag";

export const PasswordReset = template({
  id: "readable.PasswordReset",
  root: "Email",
  fields: { code: prop.text({ pattern: "^[0-9]{6}$" }), /* … */ },
  rules: {
    plugins: { lint: readable({ kind: "transactional" }) },
    require: {
      lint: ["contrast", "link-text", "lang", "target-size", "code-readout", "emoji", /* all {{REQUIRED_LINT}} */],
      core: ["layout/overflow"],
    },
    links: { domains: ["fernhill.example", "*.fernhill.example"], schemes: ["mailto"], tags: "deny" },
    root: { lang: true, title: true, previewText: true },
  },
  render: (v) => /* … */ <Text>{group(v.code)}</Text> /* "482 913" */,
});

PasswordReset.check(values);  // { valid, rules: [{ rule: "code-readout", status: "passed" }, …], snapshots }
    
  
    

    


    
  
    
    
    Conformance reports
    
    
    One per template, against WCAG 2.2 level AA. That includes WCAG 2.1 AA, which is what EN 301 549 (the standard the European Accessibility Act points to) asks for. A Hyper Elements Document, made from the template's own check().
    
    
      {{REPORT_LINKS}}
    
    
    Automated checks find many barriers, not all of them. That's why each report says which criteria a person confirms: the words, the images, and what's said about time limits. Readable's templates are written to meet those too.
